# Experimental release - 2 October 2026

This update enables verified Map control labels by default, corrects
several native prompt destinations, and repairs support-hand guidance for
noncompact firearms. Controller touch bindings can acquire VR input ownership
when their configured sensor is touched.

Supported game: The Phantom Pain 1.0.15.4, Windows x64, PC OpenXR headset.
This is an experimental prerelease.

## Changes since 1 October

- **Map control labels default on.** Place/Remove Marker shows the effective
  Confirm binding. The verified field Map footer shows Toggle MAP/NAV, Reset
  Coordinates, Switch Zoom and Zoom In/Out bindings. Native-button mode restores
  the original captions and graphics; returning to VR restores the labels.
  The launcher exposes the Map setting; the broader experimental prompt
  adapter remains separately selectable. Other footer modes, longer personal
  chords and localization still require review.
- **Correct native prompt routes.** Items Use and Commands Confirm resolve the
  native R3 destination; vehicle weapon/call resolves L1. Horse controls and
  vehicle stick clicks also use their actual native destinations. Mother Base
  Help displays the effective Menu hold.
- **Bound touch inputs acquire VR ownership.** All ten supported capacitive
  sensors can request ownership when an effective personal binding uses them.
  Touching an unbound sensor does not request ownership. Existing bindings are
  preserved during installation and updates.
- **Support-hand guidance follows the authored contact.** A noncompact firearm
  no longer rotates away from a hand already at its native support-palm point
  merely because that contact is below or beside the barrel. The compact FAKEL
  branch and native muzzle/shot axis are unchanged. Current-primary contact,
  translated contact, distant-hand rejection and one-hand release have scoped
  simulator evidence; all-weapon and physical grip acceptance remain open.
- **Binocular material preparation is corrected.** The material loader now
  distinguishes sampler binding names from texture-type names. The owned
  model and its authored material data load, but the guarded native scene
  insertion has not yet produced an accepted lighting result. Unavailable
  assets or an unknown scene pass retain the existing draw. Physical holding,
  hand aiming, zoom, acquisition and marking are preserved. The native housing
  material experiment now defaults **off** and is labeled experimental in the
  launcher.
- **iDroid alignment investigation is isolated.** Bounded diagnostics identify
  the existing native projection effect and compare its emitter with the
  published hand/device/screen frame. Diagnostics default off. Controlled cone
  fitting remains disabled in ordinary play while its native ownership and
  final-eye behavior are tested.
- **Bounded test recovery and clearer evidence.** The local runner distinguishes
  an expired movement pulse that the runtime never sampled, observes current
  popup choice separately from a completed response, and handles the verified
  completed-login notice. Capture recovery invalidates the partial eye pair
  and requires a fresh pair. These changes support testing; they do not certify
  every native menu, traversal route or recovery branch.

The weapon/status display and HUD remain on the **left bionic forearm**; the
right hand holds iDroid. Floating aiming overlays stay off. Physical optics,
Coco's scope-glass stabilization and independent lens brightness adaptation
are preserved. Desktop preview remains **1280 x 720**; VR uses the active
runtime's per-eye recommendations and eye FOVs. Local iteration refreshes the
same **play/** folder and leaves Steam running.

## Install or update

Close MGSV, extract the complete ZIP and open **MGS5VR-Launcher.exe**. Select
your owned `mgsvtpp.exe`, then choose **Install VR** or **Update / Keep My Settings**.
Connect PC VR, leave Steam signed in and choose **Launch**. `Launch-Headset.cmd`
is also included. Personal settings and bindings are preserved.

`RELEASE.json`, `BUILD.json`, `manifest.json` and `SOURCE_REVISION.txt` identify
the exact package and committed source. Retail assets are imported from the
player's own installation; saves, extracted game assets and private simulator
binaries are not distributed.
