# Native context coverage inventory

This readable inventory is rendered from [NATIVE_CONTEXT_COVERAGE.json](NATIVE_CONTEXT_COVERAGE.json), the machine-readable source of record. It is a finite first denominator and remains explicitly incomplete.

The September 26 prototype has bounded observations for the Continue route, Pause open/close, iDroid open and one tutorial acknowledgment, plus a failed posture attempt. No full native-context or physical-headset pass is claimed. The eight resolver categories in the JSON are mod input dispatch labels; they do not enumerate native game modes. `CONTROL_SCHEMA.json` remains authored guidance, not runtime evidence.

Resolve every action/axis ID against the run’s effective `mgs5vr_controls.exe --bindings-json` export. This inventory was cross-checked against the current default export; a user configuration can change or disable those routes. A bound input or sampled XR value never counts as native acceptance.

Predicate `all` clauses use strict dot-path equality and all must match; `any` is a list of alternative equality sets. Missing or stale data fails a case. `null` means no current executable predicate. Optional Lua snapshot fields must be requested explicitly by a bot case.

These obligations are not executable scenarios. A broad cue such as `demo=true` cannot authorize input to a particular cinematic. Each authored case must supply the required native subcontext, target, eligibility, outcome and exit guards; unresolved identity fields keep that case blocked.

Native script paths under `artifacts/fox-unpack/` are references into the local ignored owned-game extract. No retail code or assets are included in these tracked docs.

## Bot and field-kit use

Each record should become a state-predicated bot case with a fresh entry observation, current effective binding resolution, native outcome check and explicit exit/cancel behavior. For dynamic choices such as interrogation, use only the currently visible native options. Generate an instructional clip only after that case has current outcome evidence and captures that show the relevant controller input and native result. This inventory is not a finished guide or film.

## Explicit instrumentation work

- **gap.menu_focus** — Exact focused menu item, enabled native choices, nested menu owner, and tutorial/acknowledgment mask. Available now: The fast observer exposes title/menu/iDroid open flags; it does not expose focus or selected option.
- **gap.player_mode** — Fresh mounted/seat/emplacement role, on-foot subcontext, aim/weapon readiness, cover/hide, target eligibility, and action acceptance in one correlated native observation. Available now: The optional Lua scenario query records mission/sequence, selected player status bits, buddy and a few weapon slots; the fast control audit records one coarse resolver category and sampled inputs.
- **gap.target_interaction** — Target identity/range/eligibility, prompt kind, current CQC/hold-up/interrogation option, and resulting intel or target-state delta. Available now: No target-action contract is published in the bot snapshot; native script source describes dispatch paths but not current scene eligibility.
- **gap.cinematic_class** — Interactive versus noninteractive demo class, camera-cut generation, per-step input lock, permitted skip/cancel, and re-acquired player control. Available now: The current scene classifier sees one demo boolean and labels it cinematic.
- **gap.equipment_result** — Selected native equipment ID/grade, availability reason, effect-specific state delta, and item-specific cancel behavior across all owned eligible IDs. Available now: The fast snapshot does not enumerate the full native equipment catalog or validate item effects.
- **gap.helicopter_vehicle_role** — Native helicopter passenger/seat/weapon role, vehicle subtype, mount identity, control handoff, and exit readiness. Available now: The scenario query reports sequence and player statuses but does not publish native helicopter or emplacement role identity.
- **gap.native_action_result** — Game-consumed action result, rejection reason, and matching visible native effect. Available now: Input sampling and XR-published gamepad bits establish delivery only; they do not establish game acceptance.
